1. Hello

Install Nihil (see the home page), save this as hello.nihil and run nihil run hello.nihil. >> writes to the standard output and adds no line break of its own. nihil hello.nihil compiles it into a native executable, ./hello, instead.

>> "Hello, Nihil!\n";

Output:

Hello, Nihil!

2. Values and types

There are no declarations: a variable is created by its first assignment, and its type comes from the value and stays. The four basic types are INT, FLOAT, BOOL and STRING. Nothing converts implicitly: $ makes text, .n turns an INT into a FLOAT, #f a FLOAT into an INT (and # of a STRING or an ARRAY is its length).

count = 3;                      // INT
price = 2.5;                    // FLOAT
ready = true;                   // BOOL
name = "tea";                   // STRING
total = price * .count;         // .n turns an INT into a FLOAT
>> name + ": " + $count + " x " + $price + " = " + $total + "\n";
>> "whole part: " + $#total + "\n";     // #f turns a FLOAT into an INT
>> "letters: " + $#name + "\n";         // # of a STRING is its length
>> "ready: " + $ready + "\n";           // $ turns a value into text
n = "42".int() || 0;                    // text to number (or 0 if it is not one)
>> $(n + 1) + "\n";

Output:

tea: 3 x 2.5 = 7.5
whole part: 7
letters: 3
ready: true
43

3. Conditions and loops

There are no keywords: the expression before a { decides what the block does. A BOOL makes it an if, and } || … { continues as else if or else. An INT repeats the block that many times. A * before a BOOL makes it a while loop. And xs : x, i { … } goes over each element of an array (or each byte of a text), with its index; the names after the : are new, and belong to the block.

x = 7;
x > 10 {
    >> "large\n";
} || x > 5 {
    >> "medium\n";
} || {
    >> "small\n";
}

3 { >> "hip "; }                // an INT before { repeats the block
>> "hooray\n";

i = 1;
* i <= 5 {                      // * is a while loop
    >> $(i * i) + " ";
    i = i + 1;
}
>> "\n";

["ana", "bia", "caio"] : name, n {    // each element of an array, and its index
    >> $n + ":" + name + " ";
}
>> "\n";

Output:

medium
hip hip hip hooray
1 4 9 16 25 
0:ana 1:bia 2:caio

4. Methods

A method is a name, parameters and a block. Every parameter has a default, which gives its type, so calls may leave arguments out. : returns a value, and the type of the result is worked out from what is returned.

// every parameter has a default, and the default gives its type
greet(name = "world", times = 1) {
    times { >> "Hello, " + name + "! "; }
    >> "\n";
}

// ":" returns a value
square(n = 0) { : n * n; }

fib(n = 0) {
    n < 2 { : n; }
    : fib(n - 1) + fib(n - 2);
}

greet();
greet("Nihil", 2);
>> $square(12) + " " + $fib(20) + "\n";

Output:

Hello, world! 
Hello, Nihil! Hello, Nihil! 
144 6765

5. Arrays, text and the library

An ARRAY holds values of one type; [0 ; n] makes n copies. The library is called on a value after a ., so its names never take one from your program. $ of an ARRAY of INT makes text from its bytes, which is why show builds the text itself, one element at a time.

// a method to show an ARRAY of INT ($ of an array of INT makes text from its bytes)
show(v = [0]) {
    parts = ["" ; #v];
    v : x, i { parts[i] = $x; }         // each element, and its index
    : "[" + parts.join(", ") + "]";
}

nums = [5, 3, 8, 1];
>> $#nums + " numbers, the first is " + $nums[0] + "\n";
nums = nums + [13];                     // joining makes a new array
>> show(nums.sort()) + "\n";
>> "sum " + $nums.sum() + ", max " + $(nums.max() || 0) + "\n";

zeros = [0 ; 4];                        // 4 copies of 0
zeros[2] = 9;
>> show(zeros) + "\n";
>> $[72, 105] + "\n";                   // bytes to text: Hi

line = "  pear, apple, fig ";
words = line.trim().split(", ");        // an ARRAY of STRING
>> words.sort().join(" < ") + "\n";
>> line.trim().upper() + "\n";
>> $line.contains("apple") + "\n";

Output:

4 numbers, the first is 5
[1, 3, 5, 8, 13]
sum 30, max 13
[0, 0, 9, 0]
Hi
apple < fig < pear
PEAR, APPLE, FIG
true

6. Optionals: the value that is not there

_ is the absence of a value. A variable created with a ? may hold it; an ordinary one never does. The only way to take the value out is || with a fallback, so a missing value can never be used by accident.

// "_" is the value that is not there; a "?" when a variable is created lets it hold _
find(v = [0], x = 0) {
    v : y, i { y == x { : i; } }
    : _;                                // so find returns INT?
}

nums = [5, 8, 13];
at? = find(nums, 8);
>> at;                                  // an optional prints its value, or _
>> "\n";
at = find(nums, 99);
at == _ { >> "99 is not there\n"; }
pos = find(nums, 13) || -1;             // || takes the value, or the fallback
>> "13 is at " + $pos + "\n";
n = "12x".int() || 0;                   // the library returns optionals too
>> $n + "\n";

Output:

1
99 is not there
13 is at 2
0

7. Maps

A MAP holds values by key, in memory. Reading a key gives an optional, because the key may not be there; assigning _ deletes it.

age = {"ana": 30, "bob": 25};
age["carla"] = 41;                      // adds or replaces
age["bob"] = _;                         // deletes
>> $#age + " people\n";
>> "ana is " + $(age["ana"] || 0) + "\n";
>> "dan is " + $(age["dan"] || 0) + "\n";   // m[k] is _ when the key is not there

// counting words
counts = {"": 0 ; 16};                  // an empty map of STRING to INT
words = "the cat and the hat and the bat".split(" ");
words : w { counts[w] = (counts[w] || 0) + 1; }
counts.keys().sort() : k { >> k + "=" + $(counts[k] || 0) + " "; }
>> "\n";

Output:

2 people
ana is 30
dan is 0
and=2 bat=1 cat=1 hat=1 the=3

8. Files and input

@ reads a whole file, @>> replaces it atomically and @+>> appends to it. @? gives _ instead of an error when the file is not there. << reads a line from the input into a variable of any basic type. (The output below is with Ana typed as the input.)

@>> "notes.txt", "first line\n";        // write a file (atomically)
@+>> "notes.txt", "second line\n";      // append to it
text = @ "notes.txt";                   // read it whole
lines = text.trim().split("\n");
>> $#lines + " lines; the last: " + lines[#lines - 1] + "\n";
missing? = @? "nope.txt";               // @? gives _ instead of an error
missing == _ { >> "nope.txt is not there\n"; }

>> "Your name? ";
name = "";
<< name;                                // reads a line from the input
>> "Hello, " + name + "!\n";

Output:

2 lines; the last: second line
nope.txt is not there
Your name? Hello, Ana!

9. Tables on disk

A data model describes a record of fixed width; # marks its key. A table is a plain text file, one record per line, with a hash index on disk for reading, writing and deleting by key. Queries like where, sort and sum take an expression of the fields.

PRODUCT = @[#code: INT(4); name: STRING(12); price: FLOAT(6)];   // a data model; # marks the key
FILE = "products.dat";

@{}>> FILE, PRODUCT(1, "Coffee", 12.5);    // write by key: adds it, or replaces it
@{}>> FILE, PRODUCT(2, "Tea", 8.0);
@{}>> FILE, PRODUCT(3, "Cake", 15.0);

p = PRODUCT @{2} FILE;                      // one record by its key
p.price = 7.5;
@{}>> FILE, p;

rows = PRODUCT @ FILE;                      // the whole table
>> $rows.where(price < 13.0).sort(name);    // a query; $ turns records into table lines
>> "total: " + $rows.sum(price) + "\n";
PRODUCT @{3} FILE = _;                      // delete by key
>> $#(PRODUCT @ FILE) + " records left\n";

Output:

   1Coffee        12.5
   2Tea            7.5
total: 35.0
2 records left

10. The standard library

Libraries that ship with the compiler are included with @ "std:name.nihil";: std:env.nihil (configuration from .env and the environment), std:json.nihil (writing JSON), std:time.nihil (clocks: now_us() and now_ms() to time something) and std:mcp.nihil (an MCP server for AI agents). Reading JSON is built into the library: a JSON value stays text, and each call takes a part of it.

@ "std:env.nihil";                          // libraries that ship with the compiler
@ "std:json.nihil";

port = env_int("PORT", 8080);               // the .env file or the environment, or the default
user = env("USER", "nobody");

item = "{\"name\": \"Tea\", \"price\": 7.5, \"tags\": [\"hot\", \"green\"]}";
name = (item.json("name") || "\"\"").json_text() || "";
price = (item.json("price") || "0").float() || 0.0;
tags = (item.json("tags") || "[]").json_items();
>> name + " costs " + $price + ", " + $#tags + " tags\n";
>> "{\"port\": " + $port + ", \"ok\": " + json_bool(port > 0) + "}\n";

Output:

Tea costs 7.5, 2 tags
{"port": 8080, "ok": true}

11. Globals and locals: the one rule to remember

Variables assigned at the top level are globals, and a name that belongs to a global always means that global, even inside a method: there, total = … changes the global instead of creating a local. Give locals names no global uses. Only a parameter may share a global's name, and then it hides the global inside its method.

total = 0;                      // a global: assigned at the top level

add(n = 0) {
    total = total + n;          // changes the global: a name that is global is always the global
}

reset_counter() {
    i = 0;                      // a local: no global is called i
    * i < 3 { i = i + 1; }
}

add(5);
add(7);
>> "total: " + $total + "\n";   // 12

// a parameter may have a global's name, and then it hides the global inside its method
double(total = 0) { : total * 2; }
>> $double(21) + " " + $total + "\n";

Output:

total: 12
42 12

12. Automatic keys

A key marked #+ is numbered by the table: write a record with key 0 by key (@{}>>) and it gets the next number, which the record then holds. The counter is kept next to the table, so a deleted number is never given again and a second run goes on from where the first stopped. In the IDE, orders.dat then appears under Database, where its records can be filtered, added, changed and deleted.

ORDER = @[#+id: INT(6); client: STRING(12); total: FLOAT(8)];   // #+ : the table numbers the key
FILE = "orders.dat";

a = ORDER(0, "Ana", 42.5);              // key 0: the table gives it the next number
@{}>> FILE, a;
>> "Ana's order is #" + $a.id + "\n";    // the record now has its number

b = ORDER(0, "Bruno", 18.0);
@{}>> FILE, b;
ORDER @{b.id} FILE = _;                 // Bruno's order is deleted: its number is never given again

c = ORDER(0, "Carla", 7.25);
@{}>> FILE, c;
>> "Carla's order is #" + $c.id + "\n";

rows = ORDER @ FILE;
i = 0;
* i < #rows {
    >> "  #" + $rows[i].id + " " + rows[i].client.trim() + ": " + $rows[i].total + "\n";
    i = i + 1;
}

// Run it again: the numbers go on from where they stopped (orders.dat.nihil-seq keeps the
// counter). In the IDE, click orders.dat under Database to see, filter and change its records;
// in + Record, leave id empty and the table numbers it.

Output:

Ana's order is #1
Carla's order is #3
  #1 Ana: 42.5
  #3 Carla: 7.25

13. Modeling data

There is no database apart from the program and no schema file: the model is the schema, declared in the code, and each model is a type, so the compiler checks every field name. A table is a text file in which every line is one record of the same width: it opens in an editor, goes into git, and record i starts at byte i × the width, so one record is read or changed without loading the rest. Next to it, .nihil-idx (the index of the key) and .nihil-seq (the counter of an automatic key) are caches that are rebuilt when they are missing or out of date.

Relations are keys: a field holds the key of a record in another table (customer below holds a CUSTOMER id). The table does not enforce the link, so the program checks it when it writes (sell), and a join is a lookup by key (CUSTOMER @{s.customer} CUSTOMERS), a few small reads through the index. Behaviour goes in methods of the model (c.owes(sales)), and a field whose name starts with _ is private: only those methods read or change it (_cents at the end), so they keep the data consistent. A model can start from another (SAVINGS = @[WALLET; rate: FLOAT(5)];): its fields come first, its methods work on it, a SAVINGS goes where a WALLET is expected as an argument or as an element of a list, and its own describe replaces WALLET's: a call through a WALLET runs the record's real model's. where, count, first, sort and sum are compiled into loops where they are called.

Changing a model changes the width of its lines, so the old table no longer reads with the new model. Convert it once, reading it with the old model and writing it with the new one:

OLD = @[#id: INT(4); name: STRING(12)];
NEW = @[#id: INT(4); name: STRING(12); city: STRING(14)];

old = OLD @ "customers.dat";
new = [NEW() ; #old];
old : o, i { new[i] = NEW(o.id, o.name, ""); }
@>> "customers.dat", new;               // the same table, with the new field (empty)

Not there yet: links checked by the table, group/min/max over records, indexes on other fields than the key. Several programs may write one table by key at the same time: each write takes the table's lock, so they wait for each other. How fast all this is, from a thousand records to a million: Performance. The full rules are in SPEC §20.

// Two models, and the link between them: a sale names its customer by the customer's key.
CUSTOMER = @[#id: INT(4); name: STRING(12); city: STRING(14)];
SALE = @[#+id: INT(6); customer: INT(4); total: FLOAT(8); paid: BOOL];

CUSTOMERS = "customers.dat";
SALES = "sales.dat";

// a method of a model: what a customer owes, from the sales that point to it
CUSTOMER.owes(c = CUSTOMER(), sales = [SALE()]) {
    : sales.where(customer == c.id && !paid).sum(total);
}

// a fresh start on every run: the customers rewritten, the sales (and their counter) removed
@>> CUSTOMERS, [CUSTOMER(1, "Ana", "Lajeado"),
               CUSTOMER(2, "Bruno", "Porto Alegre"),
               CUSTOMER(3, "Carla", "Lajeado")];
SALES.remove();
(SALES + ".nihil-seq").remove();

sell(customer = 0, total = 0.0, paid = false) {
    known? = CUSTOMER @?{customer} CUSTOMERS;          // the link is checked here
    known == _ { >> "no customer " + $customer + ": sale refused\n"; :; }
    @{}>> SALES, SALE(0, customer, total, paid);
}
sell(1, 120.0, true);
sell(3, 45.5, false);
sell(1, 80.0, false);
sell(2, 300.0, true);
sell(9, 10.0, false);                   // refused: there is no customer 9

// a join by hand: each sale finds its customer by key (a few small reads, through the index)
sales = SALE @ SALES;
i = 0;
* i < #sales {
    s = sales[i];
    c = CUSTOMER @{s.customer} CUSTOMERS;
    status = "open";
    s.paid { status = "paid"; }
    >> "sale #" + $s.id + "  " + c.name.trim() + " (" + c.city.trim() + ")  ";
    >> $s.total + "  " + status + "\n";
    i = i + 1;
}

// per customer: the model's method, and queries over the sales
customers = CUSTOMER @ CUSTOMERS;
i = 0;
* i < #customers {
    c = customers[i];
    n = sales.count(customer == c.id);
    >> c.name.trim() + ": " + $n + " sale(s), owes " + $c.owes(sales) + "\n";
    i = i + 1;
}
// a join inside a query: the city of each sale's customer
lajeado = sales.where((CUSTOMER @{customer} CUSTOMERS).city == "Lajeado");
>> "sold in Lajeado: " + $lajeado.sum(total) + "\n";

// a field whose name starts with _ is private: only the model's own methods read or change it
WALLET = @[owner: STRING(12); _cents: INT(8)];
WALLET.pay(w = WALLET(), cents = 0) {
    cents > w._cents { ?! = "not enough: " + $w._cents + " cents"; }
    w._cents = w._cents - cents;
}
WALLET.left(w = WALLET()) { : w._cents; }
wallet = WALLET("Ana", 5000);
wallet.pay(1200);
?wallet.pay(9000);                      // refused by the method; wallet._cents = 0; would not compile
>> "left: " + $wallet.left() + " (" + ?! + ")\n";

// a model can start from another: SAVINGS has WALLET's fields first, and WALLET's methods
SAVINGS = @[WALLET; rate: FLOAT(5)];
savings = SAVINGS("Bia", 10000, 0.5);
savings.pay(2500);
>> savings.owner + ": " + $savings.left() + " left, at " + $savings.rate + "%\n";

// a SAVINGS goes where a WALLET is expected: as an argument, or into a list of WALLET
wallets = [WALLET() ; *];
wallets[] = wallet;
wallets[] = savings;
in_all = 0;
wallets : w { in_all = in_all + w.left(); }
>> "in all wallets: " + $in_all + "\n";

// SAVINGS replaces WALLET's describe: a call through a WALLET runs the record's own model's
WALLET.describe(w = WALLET()) { : w.owner + ": " + $w.left(); }
SAVINGS.describe(s = SAVINGS()) { : s.owner + ": " + $s.left() + " at " + $s.rate + "%"; }
wallets : w { >> w.describe() + "\n"; }

14. Errors: protected calls and blocks

A runtime error (an index past the end, a division by zero, a file that cannot be read, a broken JSON document) ends the program with its message. A ? before a call protects it: an error anywhere inside gives _ instead, and ?! holds its text (empty when the call worked). ?! = text; raises an error of your own, which a protected call catches like any other. ?{ … } protects a whole block the same way, and || { … } after it runs only when something inside failed; what the block did before the error stays done. A server keeps running when one request fails, and a program can skip a bad line of its input and go on.

// a runtime error ends the program; a "?" before a call turns it into _, and ?! says why
half(n = 0) { : 100 / n; }
r? = ?half(4);
>> r; >> " [" + ?! + "]\n";             // it worked: ?! is empty
r = ?half(0);
>> r; >> " | " + ?! + "\n";

// ?! = "why"; raises an error of your own, which a protected call catches like any other
price(text = "") {
    p? = text.float();
    p == _ { ?! = "not a price: " + text; }
    : p || 0.0;
}
total = 0.0;
["12.5", "abc", "3"] : t {
    v? = ?price(t);
    v != _ { total = total + (v || 0.0); } || { >> "skipped, " + ?! + "\n"; }
}
>> "total " + $total + "\n";

// ?{ … } protects a whole block; || { … } runs only when something inside failed
rows = [3, 0, 5];
sum = 0;
?{
    rows : n { sum = sum + 60 / n; }
} || {
    >> "stopped at a bad row (" + ?! + "), sum so far " + $sum + "\n";
}

Output:

25 []
_ | division by zero
skipped, not a price: abc
total 15.5
stopped at a bad row (division by zero), sum so far 20

15. Lists: arrays that grow

An ARRAY keeps the size it was made with. A LIST grows: [x ; *] makes an empty one (x only gives the type of its items), v[] = x; adds at the end, and v[i], #v and the each loop work as on an ARRAY. Like a MAP, it is shared: every name and every method that receives it sees the same items. [x ; *1000] makes room for 1,000 items at first, when the size is roughly known. The methods of ARRAY work on a copy of the items, and v.array() gives that copy, an ARRAY of fixed size.

// [x ; *] makes an empty LIST; x only gives the type of its items
names = ["" ; *];
names[] = "carla";                      // adds at the end
names[] = "ana";
names[] = "bob";
>> $#names + " names, the second is " + names[1] + "\n";
names[0] = "Carla";                     // changes an item, as in an ARRAY

// keep the numbers above 10
nums = [5, 12, 7, 20, 3, 18];
big = [0 ; *];
nums : n { n > 10 { big[] = n; } }
big : b, i { >> $i + ": " + $b + "\n"; }

// a LIST is shared: a method that receives it adds to the same items
shout(into = ["" ; *], word = "") { into[] = word.upper() + "!"; }
shout(names, "dora");
>> $#names + " names\n";

// the methods of ARRAY work on a copy of the items; array() gives the copy itself
>> names.sort().join(" < ") + "\n";
>> $names.contains("bob") + "\n";
plain = names.array();                  // an ARRAY of STRING, with a fixed size
>> $#plain + "\n";

Output:

3 names, the second is ana
0: 12
1: 20
2: 18
4 names
Carla < DORA! < ana < bob
true
4

16. Objects: the five pillars

Nihil has no classes, but a model with methods works as one: the model is the class, each record an object, and the five pillars of object orientation are there. Abstraction: a method whose body is ... is abstract ({ ... : 0; } gives an example of what it returns), and a model that leaves one unimplemented makes no records. Encapsulation: a field whose name starts with _ is read and changed only by its model's own methods. Inheritance: CHECKING = @[ACCOUNT; overdraft: INT(10)]; starts from ACCOUNT's fields and has all its methods. Polymorphism: a child goes where its parent is expected, and a call through the parent runs the method of the record's real model. Below, withdraw is written once, and each account pays its own fee.

On disk, the model is also the table, with no mapping in between: CHECKING @ file gives CHECKINGs with their methods, a record read by its key is changed by its methods and written back by its key, and a change in memory stays there until it is written. A query calls the model's methods by name, on each record: count(balance() > 10000). Each table holds one model, since its lines have one width; a LIST of the parent gathers several. There is no super and no interfaces; the rules are in SPEC §20.7 to §20.11.

// Objects with the five pillars: a model is a class, a record is an object, and its methods are
// the model's (SPEC §20.7 to §20.11). One example, bank accounts, goes through each pillar.

// money(1234) is "12.34": amounts are kept in cents, as INTs
money(c = 0) {
    sign = "";
    c < 0 { sign = "-"; c = 0 - c; }
    pad = "";
    c % 100 < 10 { pad = "0"; }
    : sign + $(c / 100) + "." + pad + $(c % 100);
}

// 1. Abstraction: ACCOUNT says what every account does, not how. A method whose body is ... is
//    abstract; the value after : is only an example of what it returns. ACCOUNT itself is abstract:
//    ACCOUNT(9, "x", 0) would not compile, since nothing tells it its fee or its kind.
ACCOUNT = @[#id: INT(4); owner: STRING(10); _cents: INT(10)];
ACCOUNT.fee(a = ACCOUNT(), cents = 0) { ... : 0; }       // what a withdrawal of cents costs
ACCOUNT.kind(a = ACCOUNT()) { ... : ""; }

// 2. Encapsulation: a field whose name starts with _ is private. Only ACCOUNT's own methods read or
//    change _cents, so the balance moves only through deposit and withdraw, and their checks.
ACCOUNT.balance(a = ACCOUNT()) { : a._cents; }
ACCOUNT.limit(a = ACCOUNT()) { : 0; }                    // how far below zero it may go
ACCOUNT.deposit(a = ACCOUNT(), cents = 0) {
    cents <= 0 { ?! = "a deposit must be positive"; }
    a._cents = a._cents + cents;
}
ACCOUNT.withdraw(a = ACCOUNT(), cents = 0) {
    cost = cents + a.fee(cents);                         // the real model's fee
    cost > a._cents + a.limit() { ?! = a.owner.trim() + " cannot take " + money(cost); }
    a._cents = a._cents - cost;
}
ACCOUNT.describe(a = ACCOUNT()) { : a.kind() + " " + a.owner.trim() + ": " + money(a._cents); }

// 3. Inheritance: a model can start from another. CHECKING and SAVINGS have ACCOUNT's fields
//    first, then their own, and every method of ACCOUNT. (Their own methods still cannot read
//    _cents: it is ACCOUNT's. They go through balance and deposit, like everyone else.)
CHECKING = @[ACCOUNT; overdraft: INT(10)];
SAVINGS = @[ACCOUNT; rate: INT(4)];                      // interest per thousand, per month

// 4. Polymorphism: each model gives its own fee and kind, and CHECKING replaces limit. A call
//    through an ACCOUNT runs the method of the record's real model: withdraw, written once in
//    ACCOUNT, charges each account its own fee and lets each go as far as its own limit.
CHECKING.kind(c = CHECKING()) { : "checking"; }
CHECKING.fee(c = CHECKING(), cents = 0) { : 150; }      // 1.50 for each withdrawal
CHECKING.limit(c = CHECKING()) { : c.overdraft; }
SAVINGS.kind(s = SAVINGS()) { : "savings "; }
SAVINGS.fee(s = SAVINGS(), cents = 0) { : cents / 100; }  // 1% of what is taken
SAVINGS.add_interest(s = SAVINGS()) { s.deposit(s.balance() * s.rate / 1000); }

// 5. Objects: each record is an object of its model, made by the model's name with every field in
//    order (the parent's first). A LIST of ACCOUNT holds any account; [ACCOUNT() ; *] only gives
//    its type, so no ACCOUNT is made.
ana = CHECKING(1, "Ana", 10000, 5000);                   // id, owner, _cents, then overdraft
bia = SAVINGS(2, "Bia", 200000, 5);
accounts = [ACCOUNT() ; *];
accounts[] = ana;
accounts[] = bia;

ana.withdraw(12000);                                     // into the overdraft, plus the fee
?ana.withdraw(5000);                                     // past the limit: refused, nothing taken
>> "refused: " + ?! + "\n";
bia.withdraw(50000);                                     // the fee is 1%: 500.00 and 5.00
bia.add_interest();
// ana._cents = 0;  would not compile: _cents is private to ACCOUNT
accounts : a { >> a.describe() + "\n"; }
in_all = 0;
accounts : a { in_all = in_all + a.balance(); }
>> "in all: " + money(in_all) + "\n";

// 6. Objects on disk: the model is also the table, with no mapping in between. Its fields are the
//    columns, the key #id is CHECKING's and SAVINGS's too, and a read gives records of the model
//    named, with its methods and private fields. One model per table: the lines have one width.
CHECKING_FILE = "checking.dat";
SAVINGS_FILE = "savings.dat";
@>> CHECKING_FILE, [ana, CHECKING(3, "Caio", 300, 0)];
@>> SAVINGS_FILE, [bia];

from_disk = [ACCOUNT() ; *];                             // ACCOUNT @ a file would not compile
(CHECKING @ CHECKING_FILE) : c { from_disk[] = c; }
(SAVINGS @ SAVINGS_FILE) : s { from_disk[] = s; }
from_disk : a { >> "read: " + a.describe() + "\n"; }

// one record by its key, changed by its methods (their checks too), written back by its key:
// a change in memory stays there until it is written
caio = CHECKING @{3} CHECKING_FILE;
caio.deposit(10000);
caio.withdraw(2500);
@{}>> CHECKING_FILE, caio;
>> "on disk: " + (CHECKING @{3} CHECKING_FILE).describe() + "\n";
>> "savings at 0.5% or more: " + $(SAVINGS @ SAVINGS_FILE).count(rate >= 5) + "\n";
// a query can call the model's methods: balance() and fee(…) are each record's, by its real model
>> "over 100.00: " + $from_disk.count(balance() > 10000) + ", fee of 100.00 in all: " + money(from_disk.sum(fee(10000))) + "\n";
